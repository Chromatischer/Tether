Tether TUI — Visual & UX Redesign

Real conversations run over Signal & Discord connectors. The TUI is the operator's cockpit: where you test the agent, watch what it's doing, and debug when it misbehaves. This plan re-frames the interface around that job — legible by default, deeply inspectable on demand — while keeping the existing ANSI-256 palette so it stays sharp over plain SSH.

Design principles

1
Debug-first chat.

Every agent turn is inspectable: model, latency, token cost, tool calls with args/results/timing, signed reasoning, and request ID — without leaving the chat.

2
Persistent status bar.

A bottom bar always present: context window usage, tokens this turn, active runs, latency, and live connector health. The cockpit instrument cluster.

3
Connector-aware everywhere.

Signal / Discord / proactive-jobs health is glanceable in the header and drillable in a dedicated Console — because those channels are where the agent actually lives.

4
One consistent visual language.

Formalized state tokens (running / ok / error / warn / reasoning) and a single gutter grammar. Same glyphs, colors, and spacing across every screen.

5
Inspector on a keystroke.

ctrl+o splits in a right pane pinning the selected turn's full internals + session metrics. Collapses to zero cost on narrow terminals.

6
SSH-honest.

Degrades cleanly: no truecolor dependence, gradient/Unicode fallbacks already detected via TerminalProfile stay respected.

Chat — default view

The header gains a live connector cluster and model badge. Messages get a compact timestamp + role gutter. A new status bar replaces the old hint-only line with real instrumentation. Composer hints fold into it.

Before

  • No timestamps; hard to correlate with connector logs.
  • Tool calls collapse to just a name — no timing, no result hint.
  • Reasoning shares the gray "tool result" style.
  • Bottom line shows only static key hints.
  • Model / token / latency invisible unless you run /status.

After

  • Every row timestamped; copy-paste-able for bug reports.
  • Tool rows: state glyph, ms timing, collapsed result preview.
  • Reasoning = violet ◈, its own channel.
  • Status bar = ctx gauge, turn tokens, latency, active runs.
  • Per-turn metadata always on the assistant header.

Inspector panel — ctrl+o

The flagship debug feature. Splits the chat and pins a right pane to the selected turn (click any message to select). Shows the full request lifecycle: timeline, every tool call with raw args/results, signed reasoning, token breakdown, and the exact model + params. On terminals narrower than ~100 cols it auto-collapses and ctrl+o overlays instead.

Tool-call states

One grammar, three states. Collapsed by default with a result preview; click or ⏎ to expand.

Debug Console (rename of Admin)

The Admin tab becomes Console — the operations dashboard. New top-of-screen connector health strip shared across sub-tabs, a live audit tail, and a sessions list so you can see every active connector conversation, not just the TUI one.

Login — refined

Lighter touch: same centered card, but a connector/build status footer so the operator sees system state before authenticating.

Suggested rollout

Incremental, each phase shippable and independently reviewable. No change to the Bubble Tea update cycle.

Phase 1

Tokens & status bar. Add cyan/violet/warn to styles.go; formalize state-glyph helpers; build the bottom status bar in chat.go (ctx gauge, tokens, latency, runs) folding the existing hint line into it. Pure rendering, low risk.

Phase 2

Message redesign. Timestamps + role gutters; assistant header metadata (model · latency · tokens, already on agentReplyMsg); reasoning → violet channel; tool rows get timing + collapsed result preview.

Phase 3

Header connector cluster. Live Signal/Discord/jobs dots + model badge in renderHeader, fed by a lightweight poll (reuse the existing 3s notification tick).

Phase 4

Inspector pane. ctrl+o split with per-turn metadata, timeline, and raw tool args/results. Auto-collapse/overlay under ~100 cols. Largest piece — selection state + a new sub-model.

Phase 5

Console. Rename Admin → Console; shared connector health strip; live audit tail; new sessions sub-tab listing per-channel conversations.

Scope guardrails: palette stays ANSI-256 (SSH-safe); TerminalProfile gradient/Unicode fallbacks are honored; the Elm-style update loop is unchanged — every screen above is a render-layer change plus, for the Inspector, one new sub-model. No DB schema change is required for Phases 1–3 (metadata already flows on agentReplyMsg).
