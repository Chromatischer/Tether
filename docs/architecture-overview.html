02 · Critical paths

Follow the work, not just the folders.

These are the highest-value execution paths to keep stable while changing architecture. They share the same Agent and SQLite database but arrive through different adapters.

Interactive reply

  1. SSH portal builds a TUI session; local --term builds the same model directly.
  2. TUI login / command handler resolves user and active conversation through store.
  3. Agent.ReplyStream builds context and sends a streaming LLM request.
  4. Tool calls loop through the session registry; confirmation can suspend and resume a turn.
  5. Message, signed reasoning items, audit and UI state are persisted.

Discord or Signal message

  1. Gateway receives a DM / event and resolves its linked Tether user.
  2. It gets or creates that user’s active conversation, handles slash-like commands, and redacts incoming text.
  3. Discord may download attachments into the user’s sandbox before invoking the agent.
  4. The same agent stream produces an outbound reply; reactions represent confirmation choices.
  5. Gateway chunks / streams response back to the provider.

Proactive / scheduled work

  1. Scheduler ticks once a minute and loads rules plus users from SQLite.
  2. Engine decides what is due, applies rate limits, and spawns a scoped background run.
  3. Agent uses proactive prompt construction / self-schedule runner and can use subagents.
  4. Result attempts delivery through linked Signal / Discord gateways.
  5. Without an external route it becomes an in-app notification for the next TUI poll.
03 · Codebase inventory

Responsibilities by package.

The project is organized by technical feature. The most central dependency direction is adapters → agent/store → infrastructure, though several feature packages currently reach across that line.

cmd/

Executable entry points: server, backup, key generation, password hash, tool docs.

composition
internal/tui + portal + term

SSH transport, terminal compatibility, Bubble Tea rendering, auth and interactive UI commands.

delivery
internal/agent

Primary orchestrator: provider calls, context compaction, system prompts, tool calling, streaming, confirmations and subagent sessions.

core
internal/agent/toolset + tools

Built-in tool implementations and declarative registry/specs: filesystem, bash, web, MCP, skills, confirmation and scheduling.

capabilities
internal/store + db

SQLite query layer, schema migrations and cache-backed application state. Modernc SQLite uses WAL, foreign keys and a busy timeout.

state
internal/llm + mcp

Provider adapters for OpenRouter / DeepSeek plus stdio MCP discovery and per-user MCP enablement.

integration
internal/discord + signal

Channel-specific lifecycle, identity linking, inbound handling, outbound delivery and confirmation reactions.

delivery
internal/proactive + subagents

Periodic rules engine, self-scheduling, background subagent lifecycle and notification delivery decisions.

automation
config, sandbox, secrets, redact, userspace

Cross-cutting configuration, command isolation, encrypted secrets, content redaction and per-user on-disk workspaces.

foundation
Trust boundary

LLM ↔ tools

The agent turns model output into tool calls. The registry, per-session allow-list and confirmation flow are the main policy gates.

Trust boundary

Remote identity ↔ local account

SSH portal access and in-app user login are intentionally separate. Discord and Signal are joined through link codes stored in SQLite.

Trust boundary

Tool sandbox ↔ host

Normal bash uses bubblewrap with no network. Host bash is config-gated and requires an explicit confirmation per call.

Operational constraint

Migration baseline

The active release baseline is v0.7 / 0020; existing databases older than it are rejected and must upgrade via an earlier compatible release.
